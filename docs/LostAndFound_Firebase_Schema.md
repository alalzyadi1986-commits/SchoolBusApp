# تخطيط هيكل بيانات Firebase لميزة "لوحة المفقودات الذكية" (محدث)

## 1. الهدف
يهدف هذا المستند إلى تحديد هيكل البيانات المقترح لميزة "لوحة المفقودات الذكية" في Firebase Realtime Database، بالإضافة إلى توضيح كيفية ربط هذه البيانات بين مختلف أدوار المستخدمين (المرافقة، الأهل، الإدارة، السائق) لضمان تدفق سلس للمعلومات، مع إضافة إمكانية تبليغ ولي الأمر عن مفقودات ابنه.

## 2. هيكل البيانات المقترح في Firebase

سيتم إنشاء مسار رئيسي جديد في Firebase يسمى `lostAndFound` داخل كل `schoolId`. هذا المسار سيحتوي على قائمة بالعناصر المفقودة (التي تم العثور عليها) والعناصر المبلغ عنها (التي فقدها الأهل).

```json
{
  "schools": {
    "schoolId_1": {
      "lostAndFound": {
        "lostItemId_1": {
          "schoolId": "schoolId_1",
          "type": "found",                  // جديد: "found" (المرافقة وجدت) أو "lost" (ولي الأمر أبلغ)
          "busId": "driverUsername_1",        // اسم المستخدم للسائق الذي يقود الباص الذي وجدت فيه المفقودات أو الذي يركبه الطالب
          "itemName": "جاكيت أزرق",
          "itemDescription": "جاكيت أزرق اللون، مقاس صغير، عليه شعار المدرسة",
          "itemImageURL": "https://firebasestorage.googleapis.com/.../jacket.jpg", // رابط الصورة في Firebase Storage
          "foundBy": "staffUsername_1",       // اسم المستخدم للمرافقة أو المدير الذي وجد العنصر (فقط لـ type: "found")
          "foundByName": "اسم المرافقة",
          "foundAt": "2026-06-01T10:30:00Z",    // تاريخ ووقت العثور على العنصر (ISO 8601) (فقط لـ type: "found")
          
          "reportedByParentUsername": null, // جديد: اسم المستخدم لولي الأمر الذي أبلغ عن المفقود (فقط لـ type: "lost")
          "reportedByParentName": null,     // جديد: الاسم الكامل لولي الأمر الذي أبلغ عن المفقود (فقط لـ type: "lost")
          "reportedAt": null,               // جديد: تاريخ ووقت التبليغ عن المفقود (فقط لـ type: "lost")
          "studentId": null,                // جديد: معرف الطالب الذي فقد العنصر (فقط لـ type: "lost")
          "studentName": null,              // جديد: اسم الطالب الذي فقد العنصر (فقط لـ type: "lost")

          "status": "active",                 // جديد: الحالات المحتملة: "active" (نشط/مفتوح), "resolved" (تم الحل/الإرجاع)
          "claimedByParentUsername": null,    // اسم المستخدم لولي الأمر الذي طالب بالعنصر (لـ type: "found")
          "claimedByParentName": null,
          "claimedAt": null,                  // تاريخ ووقت المطالبة بالعنصر
          "returnedToParentUsername": null,   // اسم المستخدم لولي الأمر الذي استلم العنصر
          "returnedAt": null,                 // تاريخ ووقت إعادة العنصر
          "returnConfirmedByStaff": false,    // تأكيد المرافقة أو الإدارة على تسليم العنصر
          "returnConfirmedByParent": false,   // تأكيد ولي الأمر على استلام العنصر
          "foundByStaffAfterLostReport": null // جديد: اسم المستخدم للمرافقة التي وجدت العنصر بعد بلاغ ولي الأمر (لـ type: "lost")
        },
        "lostItemId_2": {
          // ... عنصر مفقود آخر
        }
      }
    }
  }
}
```

### شرح الحقول المحدثة والجديدة:
*   `type`: **جديد**. يحدد نوع الإدخال: `"found"` إذا تم العثور على العنصر بواسطة المرافقة/الإدارة، أو `"lost"` إذا أبلغ ولي الأمر عن فقدان عنصر.
*   `busId`: معرف السائق (username) للباص. يستخدم لـ `type: "found"` لتحديد الباص الذي وجد فيه العنصر، ولـ `type: "lost"` لتحديد الباص الذي يركبه الطالب الذي فقد العنصر.
*   `foundBy`, `foundByName`, `foundAt`: تستخدم فقط عندما يكون `type: "found"`.
*   `reportedByParentUsername`: **جديد**. اسم المستخدم لولي الأمر الذي أبلغ عن فقدان العنصر (يستخدم لـ `type: "lost"`).
*   `reportedByParentName`: **جديد**. الاسم الكامل لولي الأمر الذي أبلغ عن فقدان العنصر (يستخدم لـ `type: "lost"`).
*   `reportedAt`: **جديد**. ختم زمني لتاريخ ووقت التبليغ عن المفقود (يستخدم لـ `type: "lost"`).
*   `studentId`: **جديد**. معرف الطالب الذي فقد العنصر (يستخدم لـ `type: "lost"`).
*   `studentName`: **جديد**. اسم الطالب الذي فقد العنصر (يستخدم لـ `type: "lost"`).
*   `status`: **محدث**. حالة العنصر. `"active"` (نشط، سواء كان معثوراً عليه وينتظر المطالبة، أو مفقوداً وينتظر العثور عليه) أو `"resolved"` (تم الحل، أي تم إرجاعه لمالكه).
*   `claimedByParentUsername`, `claimedByParentName`, `claimedAt`: تستخدم عندما يكون `type: "found"` ويطالب ولي أمر بالعنصر.
*   `returnedToParentUsername`, `returnedAt`, `returnConfirmedByStaff`, `returnConfirmedByParent`: تستخدم لتتبع عملية الإرجاع لكلا النوعين.
*   `foundByStaffAfterLostReport`: **جديد**. اسم المستخدم للمرافقة التي وجدت العنصر بعد بلاغ ولي الأمر (يستخدم لـ `type: "lost"` عندما يتم العثور عليه).

## 3. تدفق العمل والتفاعلات بين الأدوار (محدث)

### 3.1. المرافقة / الإدارة (Staff / School Admin)
*   **العثور على عنصر (Found Item):**
    1.  تفتح المرافقة (أو المدير) واجهة "لوحة المفقودات".
    2.  تضغط على زر "إضافة عنصر معثور عليه".
    3.  تلتقط صورة، تكتب وصفاً، وتحدد `busId`.
    4.  يتم حفظ البيانات في Firebase مع `type: "found"` و `status: "active"`.
    5.  يتم إرسال إشعار لجميع أولياء الأمور المرتبطين بهذا الباص.
*   **متابعة المفقودات المبلغ عنها (Lost Item Reports):**
    1.  يمكن للمرافقة/الإدارة عرض قائمة بالعناصر التي أبلغ عنها الأهل (`type: "lost"`).
    2.  عند العثور على عنصر مطابق لبلاغ ولي أمر، تقوم المرافقة بتحديث حالة العنصر المبلغ عنه إلى `status: "resolved"` وتعيين `foundByStaffAfterLostReport`.
    3.  تتلقى المرافقة إشعاراً عند مطالبة ولي أمر بعنصر معثور عليه.
    4.  بعد تسليم العنصر، تقوم المرافقة بتحديث حالة العنصر إلى `status: "resolved"` وتعيين `returnConfirmedByStaff: true`.

### 3.2. ولي الأمر (Parent)
*   **عرض المعثورات (Found Items):**
    1.  يعرض تطبيق ولي الأمر قائمة بالعناصر المعثور عليها (`type: "found"`) في باص ابنه فقط، والتي حالتها `status: "active"`.
    2.  إذا تعرف ولي الأمر على عنصر، يضغط على زر "هذا لولدي".
    3.  يتم تحديث العنصر في Firebase: `status: "active"` (مع تغيير `claimedByParentUsername`، `claimedByParentName`، `claimedAt`).
    4.  يتم إرسال إشعار إلى المرافقة/الإدارة التي وجدت العنصر وإلى السائق.
*   **التبليغ عن مفقود (Report Lost Item):**
    1.  يفتح ولي الأمر واجهة "التبليغ عن مفقود".
    2.  يختار ابنه، يصف العنصر المفقود، ويرفع صورة إن أمكن.
    3.  يتم حفظ البيانات في Firebase مع `type: "lost"` و `status: "active"`، وتعيين `reportedByParentUsername`, `reportedByParentName`, `studentId`, `studentName`, `busId`.
    4.  يتم إرسال إشعار إلى المرافقة/الإدارة والسائق المرتبطين بباص الطالب.
*   **تأكيد الاستلام:**
    1.  بعد استلام العنصر (سواء كان معثوراً عليه أو تم العثور عليه بعد بلاغ)، يمكن لولي الأمر تأكيد الاستلام في التطبيق.
    2.  يتم تحديث العنصر في Firebase: `returnConfirmedByParent: true`.

### 3.3. السائق (Driver)
*   **الاطلاع على المفقودات والمعثورات:**
    1.  يمكن للسائق عرض قائمة بالعناصر المفقودة والمعثور عليها المرتبطة بباصه.
    2.  يتلقى إشعاراً عندما يتم المطالبة بعنصر من باصه، أو عندما يتم الإبلاغ عن مفقود في باصه.
    3.  هذا يساعد السائق في تذكر تسليم العنصر لولي الأمر في اليوم التالي، أو البحث عن عنصر مفقود.

### 3.4. المدير (School Admin)
*   **الإشراف العام:**
    1.  يمكن للمدير عرض جميع العناصر المفقودة والمعثور عليها في المدرسة.
    2.  يمكنه تصفية العناصر حسب الباص، الحالة، النوع، أو تاريخ العثور/التبليغ.
    3.  يمكنه التدخل يدوياً لتغيير حالة عنصر أو تعديل بياناته إذا لزم الأمر.

## 4. الإشعارات (Push Notifications) (محدث)

لضمان فعالية النظام، سيتم استخدام `expo-notifications` لإرسال الإشعارات في الحالات التالية:
*   **من المرافقة إلى الأهل:** عند نشر عنصر معثور عليه جديد (`type: "found"`) في باص معين، يتم إرسال إشعار لجميع أولياء الأمور المرتبطين بهذا الباص.
*   **من الأهل إلى المرافقة/السائق:** عند مطالبة ولي أمر بعنصر معثور عليه (`type: "found"`)، يتم إرسال إشعار للمرافقة التي وجدت العنصر وللسائق لإبلاغهم بالمطالبة.
*   **من الأهل إلى المرافقة/السائق/الإدارة:** عند تبليغ ولي أمر عن مفقود (`type: "lost"`)، يتم إرسال إشعار للمرافقة والسائق المرتبطين بباص الطالب، وللإدارة.
*   **من المرافقة/الإدارة إلى الأهل:** عند تحديث حالة عنصر (سواء `"found"` أو `"lost"`) إلى `"resolved"`، يتم إرسال إشعار لولي الأمر المعني.

## 5. الاعتبارات الأمنية (محدث)
*   **قواعد Firebase Security Rules:** يجب تحديث قواعد Firebase لضمان أن:
    *   المرافقات والمدراء فقط يمكنهم إضافة وتعديل حالة العناصر من نوع `"found"`.
    *   أولياء الأمور يمكنهم فقط إضافة وتعديل حالة العناصر من نوع `"lost"`.
    *   أولياء الأمور يمكنهم فقط رؤية العناصر من نوع `"found"` الخاصة بباص أبنائهم والمطالبة بها.
    *   أولياء الأمور يمكنهم فقط رؤية العناصر من نوع `"lost"` التي أبلغوا عنها.
    *   السائقين يمكنهم فقط رؤية العناصر المرتبطة بباصهم.

4.  تحديث واجهات الإدارة والسائق لعرض المفقودات والمعثورات ومتابعتها.
